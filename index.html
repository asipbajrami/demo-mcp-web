Component Descriptions

1. Input Processing Components

These components analyze the user's query and extract meaningful information from it.

Query Preprocessor

Takes the raw user query and performs initial processing tasks such as:

  • Text normalization (lowercasing, removing extra spaces)
  • Tokenization (breaking the query into words/phrases)
  • Language detection for multilingual support
  • Incorporating conversation context from previous interactions
  • Expanding abbreviations and handling synonyms

Intent Classifier

Determines what the user is trying to accomplish. For example:

  • Searching for products (search_intent)
  • Checking order status (order_status_intent)
  • Comparing items (comparison_intent)
  • Requesting specific information (info_intent)
  • Uses semantic understanding of language, not just keywords

Entity Extractor

Identifies specific data points and parameters from the query:

  • Product attributes (price, color, size)
  • Time references (dates, durations)
  • Quantities and numerical values
  • Named entities (brands, people, locations)
  • Custom domain-specific entities

Intent & Entity Resolution

Combines and reconciles the outputs from intent and entity analysis:

  • Resolves ambiguities between conflicting entities
  • Infers missing but implied entities based on intent
  • Validates that extracted entities make sense for the identified intent
  • Assigns confidence scores to intent and entity matches
  • Creates a structured representation of user needs

2. API Matching Components

These components find the most appropriate APIs to fulfill the user's request.

API Capability Matcher

Maps user intent and entities to available API capabilities:

  • Builds a semantic understanding of what each API does
  • Calculates relevance scores between user intent and API functions
  • Considers parameter compatibility with extracted entities
  • Evaluates historical performance of APIs for similar queries
  • Applies domain-specific rules for API selection

Candidate API Set

Represents the collection of potentially useful APIs:

  • Ranked list of API endpoints that could fulfill the request
  • Metadata about each API's capabilities and requirements
  • Expected inputs and outputs for each API
  • Alternative API options for each part of the request
  • Potential combinations of APIs that might work together

3. Plan Generation Components

These components create a comprehensive and optimized plan for API execution.

Dependency Resolver

Determines the relationships between different API calls:

  • Identifies which APIs need outputs from other APIs
  • Creates a directed graph of data dependencies
  • Detects and resolves circular dependencies
  • Determines which API calls can run in parallel
  • Tags required data transformations between API calls

Sequence Optimizer

Finds the most efficient execution order:

  • Minimizes the total number of API calls
  • Arranges for parallel execution where possible
  • Prioritizes faster and more reliable APIs
  • Considers API rate limits and quotas
  • Optimizes for minimal latency in the overall plan

Parameter Mapper

Maps available data to API parameters:

  • Formats entity values to match API parameter requirements
  • Creates JSONPath/XPath expressions for dependent parameters
  • Sets default values for optional parameters
  • Handles type conversions and formatting
  • Validates parameter values against API constraints

Fallback Planner

Designs alternative pathways for error cases:

  • Identifies critical failure points in the plan
  • Creates alternative API sequences for common errors
  • Sets up retry strategies with exponential backoff
  • Provides default responses for failed API calls
  • Prioritizes graceful degradation of functionality

Validation Checker

Ensures the plan will likely succeed:

  • Verifies all required parameters have values
  • Confirms API dependency chains are valid
  • Checks for potential security or permission issues
  • Estimates plan execution time and resource usage
  • Identifies edge cases that might cause problems

Plan Assembler

Creates the final structured execution plan:

  • Formats the plan in the expected JSON structure
  • Adds metadata and context for debugging
  • Includes success criteria for evaluation
  • Organizes all fallback options
  • Provides explanations for plan decisions

4. Output Component

The final product of the Planner Agent process.

Execution Plan

The comprehensive blueprint for fulfilling the user's request:

  • Complete sequence of API calls with all parameters
  • Data dependencies between calls
  • Fallback options for error handling
  • Success criteria for validating responses
  • Response processing instructions

Implementation Approaches

LLM-Centric Approach

This approach uses a large language model as the primary reasoning engine:

  • Prompt Engineering - Carefully designed prompts guide the LLM through each step of the planning process
  • Few-Shot Learning - Examples of good plans are included in context to improve output quality
  • Chain-of-Thought - The LLM is prompted to explain its reasoning at each step
  • Output Parsing - Structured output formats ensure the LLM generates valid JSON plans
  • Verification Loops - Additional LLM calls verify and improve the initial plan

Hybrid Approach

This approach combines LLMs with traditional algorithms:

  • Intent Classification - Fine-tuned language models for domain-specific intent recognition
  • Entity Extraction - Named entity recognition systems combined with regex patterns
  • Graph Algorithms - For dependency resolution and sequence optimization
  • Rule-Based Systems - For validation and constraint checking
  • Vector Embeddings - For semantic matching between intents and API capabilities
