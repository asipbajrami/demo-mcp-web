Detailed Flow Explanation

1. User Query Processing

The user asks a natural language question:

"Find me red Nike running shoes under $100 with free shipping"

The Query Processor normalizes this text by removing unnecessary words, correcting spelling, and preparing it for analysis.

2. Intent Classification

The system identifies what the user is trying to do:

Intent: product_search
Confidence: 0.98

This is clearly a product search intent (as opposed to order tracking, customer service, etc.) with high confidence.

3. Entity Extraction

The system identifies specific data points from the query:

{
  product_type: "shoes",
  sub_type: "running",
  brand: "Nike",
  color: "red",
  price_max: 100,
  features: ["free shipping"]
}

4. API Capability Matching

Based on intent and entities, the system identifies relevant APIs:

1. /products/search
  - General product search API
  - Supports filtering by multiple attributes

2. /products/filter
  - Specialized filtering API
  - More advanced filtering options

3. /shipping/options
  - Provides shipping information
  - Can filter for free shipping

4. /brand/products
  - Brand-specific product search
  - Specialized for Nike products

5. Dependency Resolution & Optimization

The system determines dependencies and the optimal order for API calls:

Optimized sequence:
1. /products/search
  - Primary search to find products
  - Apply most filters here

2. /shipping/options
  - Secondary call to verify free shipping
  - Depends on product_ids from first call

The optimizer concludes that using /products/search with brand and category filters is more efficient than calling /brand/products separately.

6. Parameter Mapping & Plan Assembly

Entities are mapped to API parameters and the final plan is assembled:

{
  "api_calls": [
    {
      "endpoint": "/products/search",
      "method": "GET",
      "parameters": {
        "category": "shoes",
        "subcategory": "running",
        "brand": "Nike",
        "color": "red",
        "price_max": 100
      }
    },
    {
      "endpoint": "/shipping/options",
      "method": "GET",
      "parameters": {
        "product_ids": "$.api_call_0.response.products[*].id",
        "filter": "free_only"
      },
      "depends_on": "api_call_0"
    }
  ],
  "fallbacks": [...],
  "success_criteria": {
    "condition": "$.api_call_1.response.products.length > 0"
  }
}

What Happens Next?

Executor Agent's Role

After the Planner Agent creates the execution plan, the Executor Agent takes over:

  1. Makes the first API call to /products/search with all the product filters
  2. Receives product results that match the basic criteria
  3. Extracts product IDs from the results
  4. Makes the second API call to /shipping/options with those product IDs
  5. Filters the results to only show products with free shipping
  6. Combines and structures the data from both API calls

Generator Agent's Role

Finally, the Generator Agent creates the response for the user:

  1. Processes the structured data from the Executor Agent
  2. Creates a natural language summary of the results
  3. Formats product information in an easy-to-read format
  4. Highlights key features like free shipping
  5. Selects appropriate UI components (product grid, filters, etc.)
  6. Returns the complete response to the user

Example User Response

"I found 6 pairs of red Nike running shoes under $100 with free shipping. The Nike Revolution 6 is the most popular at $65, with free 2-day shipping. Would you like to see all the options or refine your search further?"
